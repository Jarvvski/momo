# Changelog

All notable changes to this package are documented here, generated by
[momo](https://github.com/Jarvvski/momo).

## [0.5.0] - 2026-10-14

### Added

- Add `momo notes`, printing the changelog section for a released version so a release page needs no text extraction

## [0.4.0] - 2026-10-14

### Breaking

- Return one `packages` envelope from `release`, `candidate` and `tag`, so `--format json` is a single document and `--output` keeps every package
- Reshape the public error types: a process-free `Operation` variant, adapter-owned process detail, and structured graph errors
- Default the jj tag anchor to `@-`, and tag an uncommitted release with `momo tag --rev @`

### Added

- Sync an inherited Cargo version to the shared `[workspace.package].version` in the workspace root

### Fixed

- Preserve a hand-written changelog: momo edits only the spans it owns, so footers, unrecognised sections, HTML comments, `*` bullets and CRLF survive a release
- Recompute the release target from the last release, and refuse to release a candidate whose target has moved
- Bound every spawned git, jj and mise command with a timeout, 60 seconds by default and configurable with `command_timeout`
- Treat `.momo/version` as the record of the last minted release, and refuse to tag when it is older than the newest tag
- Report a package that has never released as `null` rather than `0.0.0`

## [0.3.0] - 2026-10-13

### Breaking

- Reject unknown `momo.toml` keys and validate `changelog`, `changes_dir` and `manifest` paths, and drop the inert `tag_kind` key

### Fixed

- Make a release atomic: stage every write and commit it together, so a failure no longer leaves the repo half-released
- Preserve user-authored reference links in the changelog footer rather than replacing the whole footer
- Reject empty change text and collapse whitespace, and refuse a fragments-mode release that would discard a changelog Unreleased section
- Reject packages whose slugs collide, and reject an ambiguous `-p` instead of silently picking the first match
- Sync a workspace-inherited `Cargo.toml` version, and fail loudly when it cannot be resolved
- Validate the release-candidate template and make version bumps overflow-safe
- Fix git remote error handling, validate tag names against git ref rules, and rank tags by semver precedence
- Preserve the line endings of a `Cargo.toml` when rewriting its version
- Detect every mise config file name, dedup the discovered package graph, and use the configured `task_env` on install
- Run spawned git, jj and mise commands non-interactively, and stamp a multi-package release with one date

## [0.2.1] - 2026-10-13

### Fixed

- Fix the README's documentation links and license badge

## [0.2.0] - 2026-10-13

### Added

- Publish to crates.io, so momo installs with cargo install momo-cli

## [0.1.1] - 2026-10-13

### Fixed

- Anchor a jj tag to the release commit, not an empty working copy
- Only warn about package discovery when the configuration declares a monorepo
- Drop the changelog Unreleased link when there is no Unreleased section

## [0.1.0] - 2026-10-13

### Added

- Record changes as `break`, `add` or `fix`, into a changelog or a fragment store
- Mint zero-aware semver releases from the unreleased changes
- Cut release candidates with `candidate` (alias `rc`), and tag them
- Read and write git and jj tags, detected automatically
- Sync the released version into a package `Cargo.toml`, format-preserving
- Discover monorepo packages via the mise task graph, and target them with `-p` or `--all`
- Install `momo:*` task wrappers into a mise task environment
- Emit JSON, `--version-only` and `--output` for CI, and gate on `status --check`
- Configure momo with an optional, lazily created `momo.toml`
- Publish release binaries for Linux and macOS on a version tag

### Fixed

- Let a release candidate be tagged, by advancing the version source
